# DOM イベント追跡 MVP — 技術・プロダクト方針

編集者向け・閲覧（検証）向けの **Chrome 拡張**で、「保存済みルールに沿って DOM を監視しイベントを取得・送信する」MVP の全体方針をまとめる。**サイトへの埋め込み SDK は、検証が終わってからでもよい**（後述）。

---

## 1. スタック

### Creator（拡張）

- **WXT + React + TypeScript** で Chrome 拡張を構築する。
- WXT は Vite ベースであり、`entrypoints` から manifest を組み立てる。**popup と content script を最小構成で持ちやすい**。

### Viewer（実行・検証）

- MVP では **埋め込みより拡張の方が検証しやすい**ため、**Viewer も Chrome 拡張**で進める（WXT + TS。content script で定義取得・DOM 監視・送信）。
- **エンドユーザー向けの埋め込み Web SDK** は、挙動が固まってから切り出してもよい（Viewer とロジックは **shared モジュールで共通化**し、差し替えだけに寄せる）。
- 役割は変わらず、保存済みイベント定義の読込、ページ上でのイベント検知、ログ送信に限定する。

### Backend / DB

- **無料〜低コストな Postgres 系 SaaS** を前提とする。
- 初期フェーズでは**定義管理とイベントログの保存先を分けず**同一 DB でよい。
- 将来ログ量が増えたら、分析向けストレージやパイプラインへ移行する前提で設計する。

## 2. リポジトリ / パッケージ分割

| 単位 | 役割 |
|------|------|
| **creator-extension** | 編集者向け拡張。一覧、要素選択、イベント設定、保存。 |
| **viewer-extension** | 実行・検証用拡張。定義取得、DOM 監視、イベント発火検知、ログ送信。（将来の **viewer-embed** とロジック共有） |
| **shared-types**（または共通 DTO） | イベントルール型、ペイロード型、判定用 enum などの共有。 |

## 3. Creator 仕様

### 構成

- **popup と content script のみ** で開始する。

### フロー

1. popup で**イベント定義一覧**を表示する。
2. **新規作成**を押すと、**対象タブで content script の選択モード**を開始する。
3. 要素選択後、**簡易 UI**でイベント種別と名前を設定し、保存する。

### 「親」「子」をユーザーに強く選ばせない方針

- 親を選ぶか子を選ぶかは、**ユーザーに複雑に選ばせない**。
- **選ばれた要素に応じて内部で自動判定**し、保存前に結果だけ見せる:
  - **「この要素を直接監視」**（≒ `element`）
  - **「このコンテナ内の対象操作を監視」**（≒ `container`）

---

## 4. 選択対象の意味（プロダクト上の解釈）

これにより **MVP では子セレクターを持たなくてもよい**。

| ユーザーの選択 | 意味 |
|----------------|------|
| **子要素を直接選んだ** | その**要素だけ**を取りたい。 |
| **親要素を選んだ** | その**親コンテナ内**で起きる、対象となりうるイベントを取りたい。 |

- **親選択時**: 「そのコンテナ内の該当イベントを**すべて**拾う」仕様に寄せる。
- **単体だけ取りたい**場合は、**子を直接選ぶ**で整理する。

---

## 5. イベント種別（MVP）

対応するイベントは次の **4 つ**のみ。

| イベント | 意味・対象 |
|----------|-------------|
| **click** | **全要素**で許可してよい。 |
| **input** | まずは **input / textarea / select** を対象。 |
| **change** | **input / select / textarea** のみ対象。 |
| **focusin** | プロダクト上は「focus」相当。**input / textarea / select** に限定。`focus` はバブリングしないが **`focusin` はバブリングする**ので実装は `focusin` を使う。 |

---

## 6. 登録時バリデーション

- **どの要素も選択自体は可能**にする一方、**選択した要素（およびその配下）に対応する子要素が存在しないイベント**は選べないようにする。

例:

- **親 div** を選んだが配下に `input` / `select` / `textarea` がない → **input / change / focusin は disabled**、**click のみ選択可**。

### 独自 ARIA の choice UI（MVP では不可）

- **radio / checkbox 相当でも、ネイティブの `input[type=radio | checkbox]` が存在しない**独自 ARIA UI は、**MVP では登録不可**とする。
- 理由: ARIA の `radio` / `radiogroup` はネイティブ input の挙動を保証せず、JavaScript 実装前提になりやすいため。

---

## 7. radio / checkbox と親コンテナ

- radio / checkbox は、**親コンテナに listener** を付けてもバブリングで拾える。
- **change** は親で受け、`event.target` が実際に変化した **input** になるため、`value` / `checked` が読める。
- したがって **radio 群や checkbox 群は親選択と相性がよい**。`name` がなくても「**このコンテナ内の選択操作を取る**」という仕様で扱える。

---

## 8. 保存モデル（MVP）

**1 ルール = 1 対象 = 1 イベント** とする。

最低限のフィールド:

| フィールド | 説明 |
|------------|------|
| `projectId` | プロジェクト識別子 |
| `name` | ルール表示名など |
| `urlPattern` | 適用 URL パターン |
| `selector` | 対象要素へのセレクター |
| `targetMode` | `element` \| `container` |
| `eventType` | `click` \| `input` \| `change` \| `focusin` |

- **親選択時も子セレクターは持たない**。
- `targetMode = container` のときは、「**この selector の内側**で起きた対象イベントを**すべて拾う**」という仕様とする。

---

## 9. Viewer 仕様（拡張。将来 embed に移植可能）

- **保存済みルールを取得**し、**DOM 監視**を行う。
- **`element` モード**: 対象要素に **直接 listener**。
- **`container` モード**: **親コンテナ**に listener を付け、`event.target` から実際に変化した子要素を読む。

### 送信ペイロード（最小）

まずは次程度で十分とする。

- `projectId`
- `ruleId`
- `eventName`
- `url`
- `timestamp`
- `targetTag`
- `targetType`
- `value`
- `checked`

---

## 10. Creator UI 方針

ユーザーに「親か子か」を細かく選ばせず、複雑さと設定ミスを減らす。

1. **デフォルトは自動判定**
2. 保存前に **「この要素を監視」** か **「このコンテナ内を監視」** を表示
3. **利用可能なイベントのみ**を出す（選べないものは **disabled**）

---

## 11. MVP 要約（チェックリスト）

- [ ] Creator は **WXT 拡張**（popup + content script）。
- [ ] Viewer は **WXT 拡張**（content script 中心。**埋め込み SDK は後追い可**）。
- [ ] **親選択** = その範囲（コンテナ）の対象イベントを拾う。**子選択** = その要素のみ。
- [ ] イベントは **click, input, change, focusin**。
- [ ] input / change / focusin は **フォーム系要素がある場合のみ**許可。
- [ ] **独自 ARIA choice UI（ネイティブ input なし）は弾く**。
- [ ] **子セレクターは持たない**。
